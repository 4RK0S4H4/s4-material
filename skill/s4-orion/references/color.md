# Color

**Tokens:** `--md-sys-color-*` (49 M3 roles) · source `tokens/src/color.tokens.json` · live: [tokens page](https://4rk0s4h4.github.io/s4-material/tokens/#color)

## How color works
Every color in S4 Orion is an **M3 color role** generated from one **seed** by Material Color Utilities. Components only
ever use roles (`primary`, `on-surface`, `surface-container-high`…), never hex values, so any seed produces a complete,
accessible scheme and no component changes.

- **Default:** monochrome (black and white). It's stored in `color.tokens.json`, generated by
  `npm run generate:color` from the seed in the file's generator block.
- **An app with a color:** set a seed at run time (`orion.js`, Phase 4). Use the **vibrant** variant when the user names a
  color ("make it green"), **fidelity** when an exact brand hex must appear as is, **tonal** for subtle or photo-sampled colors.
- **Contrast levels:** standard (0), medium (0.5) and high (1). Raising contrast regenerates every role. Never darken a
  single color by hand. High contrast follows the device's "more contrast" setting automatically.

## Roles to reach for

| Need | Role |
|---|---|
| Page background | `surface` |
| Cards, panes, list groups | `surface-container-low` (or `-lowest` / `-high` to separate nested levels) |
| Nav bar, menus | `surface-container` |
| Dialogs, search | `surface-container-high` |
| Filled text fields | `surface-container-highest` |
| Main text / secondary text | `on-surface` / `on-surface-variant` |
| The one primary action | `primary` + `on-primary` |
| Selected state (nav indicator, chips, tonal buttons) | `secondary-container` + `on-secondary-container` |
| Standout container (FAB) | `primary-container` + `on-primary-container` |
| Errors, destructive confirm | `error` + `on-error`, `error-container` + `on-error-container` |
| Dividers / control outlines | `outline-variant` / `outline` |
| Snackbars | `inverse-surface` + `inverse-on-surface`, action in `inverse-primary` |

## Do / don't
- **Do** put text on the role made for it (`on-*`). **Don't** fade text with `opacity` or alpha; use `on-surface-variant`.
- **Do** show status with a label and a tone. **Don't** rely on color alone.
- **Don't** write hex values in components or app CSS. If a color is missing, it's a role you haven't found yet.

## Guarantees
The token build checks 42 role pairs (every `on-*` pair, text on every surface, outlines at 3:1) in light, dark,
high-contrast and dark high-contrast, and fails if any drops below WCAG AA.

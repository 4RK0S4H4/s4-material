## Button

Starts an action. M3 Expressive buttons: five variants, five sizes, round or square, with a shape morph on press.

```html
<button class="s4-button" type="button"><span class="s4-icon" data-icon="add"></span>Add Bill</button>
<button class="s4-button" data-variant="tonal" type="button">Export</button>
<button class="s4-button" data-variant="outlined" data-size="xs" type="button">Filter</button>
<button class="s4-button" data-toggle aria-pressed="false" type="button">Autopay</button>
<button class="s4-button" data-color="error" type="button">Delete All Data</button>
```

| Attribute | Values | Default |
|---|---|---|
| `data-variant` | `filled`, `tonal`, `outlined`, `elevated`, `text` | `filled` |
| `data-size` | `xs` (32), `s` (40), `m` (56), `l` (96), `xl` (136) | `s` |
| `data-shape` | `round`, `square` | `round` |
| `data-color` | `error` (destructive) | — |
| `data-toggle` + `aria-pressed` | toggle button; `data-label-on/off`, `data-icon-on/off` swap label and icon | — |

**When to use what:** one **filled** button for the most important action in an area; **tonal** for a strong secondary
action; **outlined** and **text** for the rest; **elevated** only when a button sits on a busy or colored background.

**Do**
- Use Title Case labels that say what happens: "Save Changes", "Export to Excel".
- Put the icon before the label.
- Use `data-color="error"` only for the confirm button of a destructive dialog or a danger zone.

**Don't**
- Don't put two filled buttons side by side; make one tonal or outlined.
- Don't grey out the main action when there's nothing to do; hide it or explain why.
- Don't color every row's delete button red; a per-row delete is a plain icon button.

**Accessibility:** every size keeps a 48dp touch target; focus shows the M3 ring; disabled buttons use M3's 12% / 38%
opacities; forced-colors mode draws a real border. Icon-only actions use the [icon button](#icon-button), which needs
an `aria-label`.

**Tokens:** `--s4-shape-button`, `--s4-shape-button-pressed`, `--s4-size-button*`, `--md-sys-typescale-label-large-*`,
`--md-sys-motion-spring-fast-spatial` (shape morph), `--md-sys-state-*`.

## Icon Button

Runs one action with one icon. M3 Expressive icon buttons: four variants, five sizes, three widths, round or square,
toggleable, with the same press morph as the [button](#button).

```html
<button class="s4-icon-button" type="button" aria-label="Edit Bill"><span class="s4-icon" data-icon="edit"></span></button>
<button class="s4-icon-button" data-variant="filled" data-size="m" type="button" aria-label="Add Bill"><span class="s4-icon" data-icon="add"></span></button>
<button class="s4-icon-button" data-variant="tonal" data-toggle aria-pressed="false" type="button" aria-label="Remind Me"><span class="s4-icon" data-icon="notifications"></span></button>
<button class="s4-icon-button" data-toggle aria-pressed="false" aria-label="Show Amounts" data-label-on="Hide Amounts" data-icon-on="hidden" type="button"><span class="s4-icon" data-icon="visible"></span></button>
```

| Attribute | Values | Default |
|---|---|---|
| `aria-label` | what the button does, Title Case | required |
| `data-variant` | `standard`, `filled`, `tonal`, `outlined` | `standard` (no container, on-surface-variant icon) |
| `data-size` | `xs` (32), `s` (40), `m` (56), `l` (96), `xl` (136); icons 20 / 24 / 24 / 32 / 40 | `s` |
| `data-width` | `narrow`, `default`, `wide` (e.g. s: 32 / 40 / 52) | `default` |
| `data-shape` | `round`, `square` | `round` |
| `data-toggle` + `aria-pressed` | toggle; `data-icon-on/off` swap the icon, `data-label-on/off` swap the `aria-label` | — |

Toggle colors (M3 Expressive): standard selected = primary icon; filled unselected = surface-container with
on-surface-variant icon, selected = primary / on-primary; tonal unselected = secondary-container, selected = secondary /
on-secondary; outlined selected = inverse-surface. A selected toggle swaps shape (round → square, square → round).
`icon-button.js` flips `aria-pressed` and fires `s4-toggle { pressed }`; inside a selecting [button group](#button-group)
the group manages it instead.

**When to use what:** **standard** in toolbars, app bars and list rows; **filled** for the one key action in a compact
spot; **tonal** for a strong secondary action; **outlined** next to filled/tonal ones for a quieter alternative.

**Do**
- Always give an `aria-label` that names the action ("Delete Electric Co.", not "Trash").
- Use toggles for on/off states (favorite, bookmark, show amounts) and swap the label with `data-label-on`.

**Don't**
- Don't use an icon button when the icon alone isn't clear; use a [button](#button) with a label.
- Don't color a per-row delete red.

**Accessibility:** native `<button>`; 48dp touch target at every size; the M3 focus ring; toggles expose `aria-pressed`;
disabled uses M3's 12% / 38%; forced-colors mode draws a border on contained variants.

**Tokens:** `--s4-shape-icon-button`, `--md-sys-shape-corner-*` (square and pressed shapes), `--s4-size-icon-button`,
`--s4-size-button-*`, `--s4-size-icon*`, `--md-sys-motion-spring-fast-spatial` (shape morph), `--md-sys-state-*`.

## Button Group

Groups related buttons. A **standard** group reacts as one when pressed; a **connected** group joins buttons into a
single control for choosing between options (M3 Expressive's replacement for segmented buttons).

```html
<!-- standard: actions -->
<div class="s4-button-group">
  <button class="s4-button" data-variant="tonal" type="button">Edit</button>
  <button class="s4-button" type="button">Mark Paid</button>
</div>

<!-- connected, single select -->
<div class="s4-button-group" data-connected data-select="single" aria-label="Period">
  <button class="s4-button" data-variant="tonal" type="button" value="week">Week</button>
  <button class="s4-button" data-variant="tonal" type="button" value="month" aria-pressed="true">Month</button>
  <button class="s4-button" data-variant="tonal" type="button" value="year">Year</button>
</div>
```

| Attribute (on the group) | Values | Default |
|---|---|---|
| `data-connected` | buttons 2dp apart, outer corners full, inner corners large (xs medium, l extra-large, xl extra-extra-large); the selected button morphs fully round | standard: 8dp apart |
| `data-select` | `single` (exactly one pressed, radio-like), `multi` (each toggles) | none: plain buttons |
| `data-fit` | `content`: as wide as the labels | connected groups stretch to fill (equal weights) |
| `aria-label` | names the choice ("Period") | — |

Children are `.s4-button` or `.s4-icon-button`; the group follows their `data-size`. Standard groups have the M3
Expressive press interaction: the pressed button widens ~15% while its neighbours give way (fast-spatial spring).

**Behaviour** (`button-group.js`): manages `aria-pressed` for `data-select`, fires `s4-change { value, values, button }`
on the group (`value` is the pressed button's `value` attribute, or the array of values for multi). Connected and
selecting groups are one tab stop (roving tabindex): Arrow keys move focus (RTL aware), Home / End jump, Space / Enter
press; disabled buttons are skipped. Groups get `role="group"`.

**When to use what:** connected + `single` for 2–5 mutually exclusive views or filters (Week / Month / Year);
connected + `multi` for independent options shown together; standard for a set of related actions.

**Do**
- Give each button a `value` and the group an `aria-label`.
- Keep labels short and parallel; use the same variant and size for every button in a group.

**Don't**
- Don't put more than five options in a connected group; use a select or chips.
- Don't mix connected groups with unrelated actions.

**Accessibility:** buttons stay native `<button>`s with `aria-pressed`; one tab stop per group with arrow keys; focus
ring stays above neighbours; forced-colors mode draws borders.

**Tokens:** `--s4-space-2` (gap), `--md-sys-shape-corner-*` (inner, pressed and selected corners),
`--md-sys-motion-spring-fast-spatial` (press and shape morph), plus the button and icon-button tokens.

## FAB

The floating action button holds the most important action on a screen. M3 Expressive sizes: FAB 56, medium 80,
large 96, each also as an extended FAB with a label.

```html
<button class="s4-fab" type="button" aria-label="Add Bill"><span class="s4-icon" data-icon="add"></span></button>
<button class="s4-fab" data-size="m" data-color="secondary-container" type="button">
  <span class="s4-icon" data-icon="camera"></span><span class="s4-fab-label">Scan Receipt</span>
</button>
<button class="s4-fab" data-fixed type="button"><span class="s4-icon" data-icon="add"></span><span class="s4-fab-label">Add Bill</span></button>
```

| Attribute | Values | Default |
|---|---|---|
| `data-size` | (default) 56 · corner large · icon 24 · label title-medium; `m` 80 · large-increased · 28 · title-large; `l` 96 · extra-large · 36 · headline-small | 56 |
| `data-color` | `primary-container`, `secondary-container`, `tertiary-container`, `primary`, `secondary`, `tertiary` | `primary-container` |
| `.s4-fab-label` | makes it an extended FAB | — |
| `data-collapsed` | folds an extended FAB back to its icon (width animation), e.g. while a list scrolls | — |
| `data-fixed` | pins it 16dp from the bottom end corner, above the nav bar (inside `.s4-app`, put it in its view) and the safe area, at `--s4-z-fab` | — |
| `aria-label` | required when there's no label | — |

Elevation level 3, level 4 on hover; the shared state layer for hover / focus / press.

**Do**
- Use one FAB per screen, for a constructive action (Add Bill, Scan Receipt, Pay).
- Use the extended FAB when the icon alone isn't obvious.

**Don't**
- Don't use a FAB for minor or destructive actions (Delete, Settings).
- Don't put two FABs on one screen; use a FAB plus regular buttons.

**Accessibility:** native `<button>`, at least 56dp; icon-only FABs need `aria-label`; when collapsed, the label text stays
in the accessibility tree; forced-colors mode draws a border.

**Tokens:** `--s4-size-fab`, `--s4-size-fab-large`, `--s4-shape-fab`, `--s4-shape-fab-large`,
`--md-sys-shape-corner-large-increased`, `--md-sys-elevation-level3/4`, `--md-sys-typescale-title-medium/title-large/headline-small-*`,
`--md-sys-motion-spring-spatial` (collapse), `--s4-z-fab`.

## App Shell

The page frame: navigation, top app bar and content, adapting to the window size class (M3 canonical layout).

```html
<div class="s4-app">
  <nav class="s4-nav-rail" aria-label="Main">…</nav>
  <div class="s4-app-body">
    <header class="s4-top-app-bar">…</header>
    <main class="s4-content">
      <section class="s4-view" data-view="home" data-title="Home">…</section>
      <section class="s4-view" data-view="bills" data-title="Bills" hidden>…</section>
    </main>
  </div>
  <nav class="s4-nav-bar" aria-label="Main">…</nav>
</div>
```

| Part / attribute | Purpose |
|---|---|
| `.s4-app` | Size container named `s4-app`; a grid of rail + body, nav bar underneath. At least the full viewport height. |
| `.s4-nav-rail` | Optional. Shown from 840 (expanded), sticky at the left, full height. |
| `.s4-app-body` | Column holding the top app bar and the content. |
| `.s4-content` | Margins 16 (< 600) / 24 (≥ 600), width capped at `--s4-layout-content-max`, safe-area insets. |
| `.s4-nav-bar` | Optional. Shown under 840, sticky at the bottom. |
| `.s4-view[data-view][data-title]` | Optional sibling destinations. A nav item with the same `data-view` switches to it (shared axis) and sets the top app bar title to `data-title`. |
| `--s4-content-max` | Set on `.s4-app` to change the content cap (e.g. `none` for a full-width table). |
| `--s4-app-inset-bottom` | Read-only: how much of the bottom is covered (nav bar + home indicator). Use it to float a FAB or toolbar above the bar. |
| `.s4-page-header`, `.s4-section`, `.s4-section-title` | Page helpers: a title + actions row, a section with vertical rhythm, a section heading (title-medium, emphasized). |

| Window | Width | Navigation | Margins |
|---|---|---|---|
| Compact | < 600 | Nav bar at the bottom | 16 |
| Medium | 600–839 | Nav bar, items horizontal | 24 |
| Expanded+ | ≥ 840 | Nav rail at the left | 24 |

**Scrolling:** the window scrolls, not an inner box. On phones this keeps the browser's collapsing toolbars, pull to
refresh and scroll-to-top on status bar tap. The top app bar is sticky at the top, the rail sticky at the side, the nav
bar sticky at the bottom. Sticky keeps the nav bar in the page flow, so it never covers the last content and nothing
needs bottom padding. Size classes are container queries on `.s4-app`, so the shell also works inside a frame.

**Behaviour (`app.js`):** the nav bar and rail of one app stay in sync (same index). With views, a destination change
runs the shared axis transition (old view slides 30px toward where you came from and fades; new one slides in from the
side you're heading, spatial spring for movement, effects for fades), scrolls to the top and fires
`s4-change { view, previous }` on `.s4-app`. `S4.app.go(app, 'bills')` switches from code.

**Do**
- Use the same destinations, in the same order, in the nav bar and the rail.
- Put a FAB or floating toolbar at `bottom: calc(var(--s4-app-inset-bottom) + var(--s4-space-4))`.
- Use window scroll; if you need an inner scroller (a split pane), give that pane its own top app bar.

**Don't**
- Don't use `position: fixed` bars inside `.s4-app`; the shell already places them.
- Don't wrap `.s4-app` in another full-height scroll container: the bars are sticky to the window.

**Accessibility:** `main`, `nav` and `header` landmarks; give each `nav` an `aria-label`. Views that aren't shown are
`hidden`, so they leave the accessibility tree. Content and bars respect the notch and home indicator (`viewport-fit=cover`).

**Tokens:** `--s4-layout-margin-compact`, `--s4-layout-margin`, `--s4-layout-content-max`, `--s4-size-nav-bar`,
`--s4-z-navigation`, `--s4-motion-pattern-shared-axis-distance`, `--md-sys-motion-spring-spatial`, `--md-sys-motion-spring-effects`.

## Top App Bar

The screen's title, its navigation button and up to three actions. M3 Expressive small, medium and large bars.

```html
<header class="s4-top-app-bar">
  <button class="s4-icon-button" type="button" aria-label="Back"><span class="s4-icon" data-icon="back"></span></button>
  <div class="s4-app-bar-title-group">
    <h1 class="s4-app-bar-title">Iron Mountain</h1>
    <p class="s4-app-bar-subtitle">12 Bills · $14,880.00 This Year</p>
  </div>
  <div class="s4-app-bar-actions">
    <button class="s4-icon-button" type="button" aria-label="Search"><span class="s4-icon" data-icon="search"></span></button>
  </div>
</header>
<header class="s4-top-app-bar" data-size="large">…</header>
```

| Attribute / part | Values | Default |
|---|---|---|
| `data-size` | `medium` (112, 136 with subtitle; headline-medium), `large` (120, 152; display-small) | small (64; title-large) |
| `data-align` | `center` (small only) | start |
| `data-scrolled` | set by `top-app-bar.js` while content is under the bar | — |
| `.s4-app-bar-title-group` | `.s4-app-bar-title` + optional `.s4-app-bar-subtitle` | — |
| `.s4-app-bar-actions` | trailing icon buttons (at most 3; put the rest in a "More Options" menu) | — |
| any other child | the leading slot (navigation icon button) | — |

**When to use what:** **small** for most screens and every detail screen; **medium** or **large** for a top-level
screen where the title deserves weight (Budget, Reports). They collapse into the small bar on scroll.

**Behaviour:** sticky at the top of its scroll container (the window, or the nearest scrolling ancestor). At rest the
bar is `surface`; once content scrolls under it, `data-scrolled` switches it to `surface-container` (and glass.css turns
that into glass). Medium and large stick with a negative `top`, so only the 64dp row stays; the JS slides that row down
as the headline scrolls away, clips and fades the headline, and fades a small copy of the title (`aria-hidden`) into the
row. Changing `.s4-app-bar-title` text updates the copy.

**Do**
- Use Title Case titles; keep them short enough for one line on a phone.
- Put the screen's search behind a Search action or a [search bar](#search) in the content, not in the title.

**Don't**
- Don't put text buttons and icon buttons together in the actions; use icon buttons with `aria-label`.
- Don't use medium or large on screens that also have tabs directly under the bar.

**Accessibility:** use a real heading (`h1`) for the title. Icon buttons need `aria-label`. The collapsed title copy
is hidden from assistive tech. Pads for the notch with `env(safe-area-inset-*)`.

**Tokens:** `--s4-size-top-app-bar`, `--s4-z-app-bar`, `--md-sys-color-surface` / `-surface-container`,
`--md-sys-typescale-title-large-*`, `-headline-medium-*`, `-display-small-*`, `--md-sys-motion-spring-effects`.

## Navigation Bar

Switches between 3 to 5 top-level destinations on compact and medium windows (under 840). M3 navigation bar, with M3
Expressive horizontal items from 600 wide.

```html
<nav class="s4-nav-bar" aria-label="Main">
  <a class="s4-nav-item" href="#home" data-view="home" aria-current="page">
    <span class="s4-nav-indicator"><span class="s4-icon" data-icon="home"></span></span>
    <span class="s4-nav-label">Home</span>
  </a>
  <a class="s4-nav-item" href="#bills" data-view="bills">
    <span class="s4-nav-indicator"><span class="s4-badge-host"><span class="s4-icon" data-icon="bills"></span><span class="s4-badge">3</span></span></span>
    <span class="s4-nav-label">Bills</span>
  </a>
  …
</nav>
```

| Part / attribute | Purpose |
|---|---|
| `.s4-nav-item` | `a` (navigates) or `button` (same page). 3 to 5 per bar. |
| `aria-current="page"` | The current destination: secondary-container pill, on-secondary-container icon (solid), on-surface emphasized label. |
| `.s4-nav-indicator` | The 56×32 pill around the icon; carries the state layer and focus ring. |
| `.s4-nav-label` | label-medium; on-surface-variant when not current. |
| `.s4-badge-host` + `.s4-badge` | Optional badge on the icon (see [badge](#badge)). |
| `data-view` | Ties the item to an `.s4-view` in an [app shell](#app). |

**Layout:** 80dp on surface-container. Under 600 the icon sits over the label; from 600 (the bar is its own container)
the icon and label sit side by side inside a 40dp pill. Inside `.s4-app` the bar is sticky at the bottom, pads for the
home indicator and hides from 840, where the [nav rail](#nav-rail) takes over.

**Behaviour (`nav-bar.js`):** clicking an item moves `aria-current` to it and fires `s4-change { item, index, value }`
on the bar (`value` = `data-view`, else `href`). `preventDefault()` in a click handler vetoes it. The new pill expands
from half width and fades in (spatial / effects springs, pure CSS, so changing `aria-current` from code animates too).

**Do**
- Use short, one-word Title Case labels; always show labels.
- Keep the same destinations and order as the rail.

**Don't**
- Don't use it for actions (use a FAB or toolbar) or for more than 5 destinations.
- Don't hide labels on unselected items.

**Accessibility:** a `nav` landmark with `aria-label`; `aria-current="page"` announces the current destination. Every
item is a full-height cell (≥ 48dp target). The focus ring wraps the pill. Forced colors: the current pill uses
Highlight and the bar gets a top border.

**Tokens:** `--s4-size-nav-bar`, `--s4-size-nav-indicator-width/height`, `--s4-shape-nav-indicator`,
`--md-sys-color-surface-container`, `--md-sys-color-secondary-container`, `--md-sys-typescale-label-medium-*`,
`--md-sys-state-*`, `--md-sys-motion-spring-spatial`, `--md-sys-motion-spring-effects`.

## Navigation Rail

Top-level destinations at the side of expanded windows (840 and up). M3 Expressive rail: collapsed (96dp) or expanded,
with an optional menu button and FAB. Uses the same `.s4-nav-item` as the [navigation bar](#nav-bar) (styles in
`nav-bar.css`).

```html
<nav class="s4-nav-rail" aria-label="Main">
  <div class="s4-nav-rail-header">
    <button class="s4-icon-button" type="button" data-rail-toggle aria-expanded="false" aria-label="Expand Navigation"
            data-label-expand="Expand Navigation" data-label-collapse="Collapse Navigation"><span class="s4-icon" data-icon="menu"></span></button>
    <button class="s4-fab" type="button" aria-label="Add Bill"><span class="s4-icon" data-icon="add"></span><span class="s4-fab-label">Add Bill</span></button>
  </div>
  <div class="s4-nav-rail-items">
    <a class="s4-nav-item" href="#home" aria-current="page"><span class="s4-nav-indicator"><span class="s4-icon" data-icon="home"></span></span><span class="s4-nav-label">Home</span></a>
    …
  </div>
</nav>
```

| Attribute / part | Purpose |
|---|---|
| `data-expanded` | Expanded rail: wider (`--s4-nav-rail-expanded-width`, default 240), labels beside icons, label-large, a 56dp pill spanning icon and label, surface-container. |
| `[data-rail-toggle]` | Button that flips `data-expanded`; `aria-expanded` and the optional `data-label-expand/collapse` labels follow. |
| `.s4-nav-rail-header` | Menu button and FAB slot. In the collapsed rail the FAB's label is hidden (icon FAB); expanded it shows (extended FAB). |
| `.s4-nav-rail-items` | The destinations (`.s4-nav-item`, see nav bar). |

**Behaviour (`nav-rail.js`):** item clicks move `aria-current` and fire `s4-change { item, index, value }`; the toggle
fires `s4-toggle { expanded }`. The width animates on the spatial spring, labels fade in on effects; icons stay in place
because the expanded pill starts where the collapsed one did. In an [app shell](#app) the rail is sticky at full
height from 840 and mirrors the nav bar.

**Do**
- Put the screen's main action in the FAB slot; give the FAB an `aria-label` (the label is hidden when collapsed).
- Keep destinations identical to the nav bar.

**Don't**
- Don't put secondary actions or settings toggles in the rail.
- Don't use the rail on compact windows; use the nav bar.

**Accessibility:** `nav` landmark with `aria-label`; `aria-current="page"`; the toggle exposes `aria-expanded`. Items keep
≥ 48dp targets. Forced colors: the rail gets an end border.

**Tokens:** `--s4-size-nav-rail`, `--s4-size-nav-indicator-*`, `--s4-shape-nav-indicator`, `--s4-size-icon-button`,
`--md-sys-color-surface` / `-surface-container`, `--md-sys-typescale-label-large-*`, `--md-sys-motion-spring-spatial`.

## Tabs

Switch between related views of the same content at one level. M3 primary and secondary tabs.

```html
<div class="s4-tabs" role="tablist" aria-label="Bill Status">
  <button class="s4-tab" type="button" role="tab" id="tab-due" aria-controls="panel-due" aria-selected="true">Due</button>
  <button class="s4-tab" type="button" role="tab" id="tab-paid" aria-controls="panel-paid" aria-selected="false">Paid</button>
</div>
<div class="s4-tab-panel" role="tabpanel" id="panel-due" aria-labelledby="tab-due">…</div>
<div class="s4-tab-panel" role="tabpanel" id="panel-paid" aria-labelledby="tab-paid" hidden>…</div>
```

| Attribute | Values | Default |
|---|---|---|
| `data-variant` | `secondary` | primary |
| `data-scrollable` | tabs keep their width; the row scrolls sideways | fixed (tabs share the width) |
| `aria-selected` | `true` on the current tab | first tab |
| `aria-controls` | id of the tab's panel | — |
| icon | `<span class="s4-icon" data-icon="…">` before the label: stacked (64dp) in primary, inline in secondary | — |

**When to use what:** **primary** tabs right under the top app bar to organize the whole screen; **secondary** tabs inside
a content area (a card, a pane) to divide it further. Use **scrollable** for more than about 4 tabs on a phone.

**Behaviour (`tabs.js`):** one indicator slides between tabs on the spatial spring (content width, 3dp, rounded top for
primary; full width, 2dp for secondary). Panels switch with the shared axis pattern: the old panel slides 30px away and
fades out, the new one slides in from the side of the newly selected tab. Keys: Left / Right (wrapping), Home / End,
with automatic activation and a roving tabindex. Fires `s4-change { tab, index, panel }` on the tab list. Missing ids,
roles and `aria-labelledby` are filled in. Without JS each selected tab draws its own indicator.

**Do**
- Use short Title Case labels (one or two words) and keep the tab order stable.
- Put tabs at the top of the content they switch.

**Don't**
- Don't use tabs for a sequence of steps or for actions.
- Don't nest primary tabs inside primary tabs; use secondary tabs.

**Accessibility:** WAI-ARIA tabs pattern; the tab list is one tab stop and panels are focusable. Selected uses color
and the indicator (and a solid icon), not color alone. Inner focus ring so a scrolling row never clips it. Forced colors:
the indicator uses Highlight and the row gets a border.

**Tokens:** `--s4-size-touch-target`, `--md-sys-typescale-title-small-*`, `--md-sys-color-primary`,
`--md-sys-color-on-surface-variant`, `--md-sys-color-surface-variant` (divider), `--s4-motion-pattern-shared-axis-distance`,
`--md-sys-motion-spring-spatial`, `--md-sys-motion-spring-effects`.

```html
</div>
```

| Attribute / part | Values | Default |
|---|---|---|
| `data-color` | `vibrant` (primary-container) | standard (surface-container) |
| `data-orientation` | `vertical` | horizontal |
| `data-type` | `docked`: full width, 64dp, square corners, no shadow, home-indicator padding | floating: 64dp pill, elevation 3 |

- Use icon buttons with `aria-label`; one tonal or filled button is fine for the key action.
- Keep 3 to 6 actions; move the rest into a "More Options" menu.

**Don't**
- Don't put navigation destinations in a toolbar (use the nav bar or rail).
- Don't stack a docked toolbar and a nav bar.

**Accessibility:** WAI-ARIA toolbar pattern with `aria-label`; disabled controls are skipped. Forced colors: the toolbar
gets a border (its shape is otherwise only a background).

**Tokens:** `--s4-shape-toolbar`, `--s4-size-top-app-bar` (64), `--md-sys-color-surface-container`,

## Search

A search bar that filters the current page as you type. M3 search bar (no full-screen search view).

```html
<div class="s4-search" role="search" data-filter="#bill-list" data-filter-empty="#bill-empty">
  <span class="s4-icon" data-icon="search"></span>
  <input class="s4-search-input" type="search" placeholder="Search Bills" aria-label="Search bills">
  <button class="s4-icon-button s4-search-clear" type="button" aria-label="Clear Search" hidden><span class="s4-icon" data-icon="close"></span></button>
  <button class="s4-icon-button" type="button" aria-label="Account"><span class="s4-search-avatar">AS</span></button>
</div>
```

| Attribute / part | Purpose |
|---|---|
| `.s4-search` | 56dp, full radius, surface-container-high, up to 720 wide. `role="search"`. |
| leading `.s4-icon` or `.s4-icon-button` | the search icon, or a menu / back button |
| `.s4-search-input` | `type="search"`, body-large, placeholder in on-surface-variant |
| `.s4-search-clear` | shown while there's text; clears and refocuses |
| trailing `.s4-icon-button` / `.s4-search-avatar` | optional actions or the account avatar (32dp initials or `<img>`) |

count with `data-filter`, else `null`). Escape clears. Clicking the bar's empty space focuses the input.

**Do**
- Say what's searched in the placeholder: "Search Bills", "Search Vendors".
- Show a short empty message when nothing matches.

**Don't**
- Don't add a Search button; results update as you type.
- Don't use a search bar as a general text field.

**Accessibility:** a `search` landmark; the input needs `aria-label` (the placeholder isn't a label). The M3 focus ring
wraps the whole bar. The clear button is a real button with a label. Forced colors: the bar gets a border.

**Tokens:** `--s4-size-text-field` (56), `--s4-shape-search`, `--md-sys-color-surface-container-high`,
`--md-sys-typescale-body-large-*`, `--s4-layout-list-width` (×2 = 720 max).

## Card

Holds content and actions about one subject. M3 cards: elevated, filled and outlined, with optional media, body and
actions. Cards are content surfaces: always solid, never glass.

```html
<article class="s4-card" aria-labelledby="bill-1">
  <div class="s4-card-media"><img src="receipt.jpg" alt=""></div>
  <div class="s4-card-body">
    <h3 class="s4-card-title" id="bill-1">Iron Mountain</h3>
    <p class="s4-card-subhead">Records storage · Due Oct 28</p>
    <p class="s4-card-supporting">Offsite boxes and shredding for the Denver office.</p>
  </div>
  <div class="s4-card-actions">
    <button class="s4-button" data-variant="text" type="button">Details</button>
    <button class="s4-button" type="button">Pay Now</button>
  </div>
</article>

<a class="s4-card" data-variant="outlined" href="/bills/10451">…</a>   <!-- the whole card opens something -->
```

| Attribute / part | Values | Default |
|---|---|---|
| `data-variant` | `elevated` (surface-container-low, level 1), `filled` (surface-container-highest), `outlined` (surface + outline-variant) | `elevated` |
| `.s4-card-media` | image, video or SVG area; takes the card's top corners (bottom corners when last). `--s4-card-media-ratio` sets the aspect ratio | 16 / 9 |
| `.s4-card-body` | 16 padding; `.s4-card-title` (title-medium), `.s4-card-subhead` and `.s4-card-supporting` (body-medium, on-surface-variant) | — |
| `.s4-card-actions` | buttons, end-aligned, 8 apart; pushed to the bottom in a grid of cards | — |
| `a.s4-card`, `button.s4-card` | interactive card: state layer from base; hover raises elevated to level 2, filled and outlined to level 1 | — |
| `disabled` / `aria-disabled="true"` | container at 38%, content on-surface at 38%, outline at 12% | — |

**When to use what:** **elevated** to lift a card off a busy page; **filled** for quiet grouping; **outlined** when cards
sit on a surface of the same color or in dense grids. For a section of settings or a form, use a [pane](#pane) instead.

**Do**
- Make the whole card a link or button when it opens one thing, and keep other buttons out of it.
- Put the main figure (an amount, a count) in tabular figures.
- Keep a card's actions to two, the main one filled or tonal.

**Don't**
- Don't nest cards, or put a card inside a card-colored pane without changing one of the surfaces.
- Don't put buttons or links inside an interactive card (nested interactive content).
- Don't add glass or blur to cards.

**Accessibility:** a static card is an `<article>` labelled by its title. An interactive card is one native `<a>` or
`<button>`, so it is a single tab stop with the M3 focus ring; its text is its accessible name, so keep it short.
Forced-colors mode draws a real border.

**Tokens:** `--s4-shape-card`, `--md-sys-color-surface-container-low` / `-highest`, `--md-sys-color-surface`,
`--md-sys-color-outline-variant`, `--md-sys-elevation-level0`–`2`, `--md-sys-typescale-title-medium-*`,
`--md-sys-typescale-body-medium-*`, `--md-sys-state-*`, `--md-sys-motion-spring-fast-effects`.

<a id="pane"></a>

## Pane

S4 addition. A solid section of a page: a group of settings, a form, or a block on a dashboard. Title, optional
supporting text, then content.

```html
<section class="s4-pane" aria-labelledby="autopay">
  <h2 class="s4-pane-title" id="autopay">Autopay</h2>
  <p class="s4-pane-supporting">Pay recurring bills from your operating account on the due date.</p>
  …
</section>

<section class="s4-pane" data-color="error" aria-labelledby="danger">
  <h2 class="s4-pane-title" id="danger">Delete Workspace</h2>
  <p class="s4-pane-supporting">This deletes every bill, receipt and vendor. You can't undo this.</p>
  <div class="s4-row"><button class="s4-button" data-color="error" type="button">Delete Workspace</button></div>
</section>
```

| Attribute / part | Values | Default |
|---|---|---|
| `data-color` | `lowest` (surface-container-lowest), `high` (surface-container-high), `error` (danger zone: error-container, on-error-container) | surface-container-low |
| `.s4-pane-title` | title-medium | — |
| `.s4-pane-supporting` | body-medium, on-surface-variant, 4 below the title | — |
| `--s4-pane-padding` | override the padding | 24, or 16 under 600 |

Children are stacked 16 apart. Padding follows the space the pane sits in: 24 from the medium window class up, 16 when
compact. That's a container measurement (`cqi` against the nearest container, such as the app's content area, or the
viewport when there is none), so a pane works with or without a container ancestor. The pane is itself an inline-size
container, so lists, tables and grids inside it can adapt to it.

**When to use what:** a **pane** groups related settings or fields under a heading; a [card](#card) is one item among
many. Use `lowest` or `high` only to separate a pane from a neighbour or a parent of the same color. Use `error` once per
page, last, for destructive settings.

**Do**
- Give every pane a title in Title Case, and use supporting text in sentence case to say what the section is for.
- Use the heading level that fits the page outline (the class sets the look, not the level).

**Don't**
- Don't nest panes of the same color.
- Don't make panes glass; they are content surfaces.
- Don't fill a whole page with `data-color="error"` panes.

**Accessibility:** use `<section aria-labelledby>` so each pane is a named region. The error pane's text uses
on-error-container, which the token build checks at AA. Forced-colors mode draws a real border.

**Tokens:** `--s4-shape-pane`, `--s4-space-4`, `--s4-space-6`, `--s4-breakpoint-medium`,
`--md-sys-color-surface-container-low` / `-lowest` / `-high`, `--md-sys-color-error-container`,
`--md-sys-color-on-error-container`, `--md-sys-typescale-title-medium-*`, `--md-sys-typescale-body-medium-*`.

```html
<ul class="s4-list">

        <span class="s4-list-supporting">Due Oct 28</span>
      </span>
      <span class="s4-list-trailing"><span class="s4-list-amount">$1,240.00</span><span class="s4-status" data-tone="tertiary">Due</span></span>
    </a>
  </li>
</ul>

<ul class="s4-list" role="listbox" aria-label="Pay From">
  <li role="none"><div class="s4-list-item" role="option" aria-selected="true" data-value="operating">…</div></li>
</ul>
```

| Attribute / part | Values | Default |
|---|---|---|
| `.s4-list-item` element | `div` (static), `a` / `button` (opens or does something), `label` (toggles the checkbox or switch inside it), `[role=option]` in a listbox | — |
| `.s4-list-leading` | icon (24, on-surface-variant), `.s4-avatar` (40 circle, initials, primary-container), image (56), checkbox | — |
| `.s4-list-content` | `.s4-list-overline` (label-small), `.s4-list-headline` (body-large, one line), `.s4-list-supporting` (body-medium, on-surface-variant) | — |
| `.s4-list-trailing` | supporting text (label-small, tabular), icon, switch, `.s4-list-amount` (body-large, tabular) with a note or status under it | — |
| height | automatic: 56 one line; 72 with supporting text or overline; 88 with both (leading and trailing align to the top) | — |
| `data-lines` (list or item) | `2` (72, supporting text clamped to 1 line), `3` (88, clamped to 2 lines) | automatic |
| `aria-current` / `aria-selected="true"` | on the item (or its `li`): secondary-container, on-secondary-container | — |
| `aria-disabled="true"`, `:disabled`, or a disabled input inside | content at 38% | — |
| `data-dividers` (list) | 1px outline-variant line between items | — |
| `data-style="segmented"` (list) | M3E segmented: items 2 apart on surface-container-low (`--s4-list-segment-color`), extra-small inner corners, large outer corners per group | — |
| `.s4-list-subheader` (an `li`) | title-small, on-surface-variant; starts a group; optional `.s4-list-subtotal` at the end | — |
| `role="listbox"` + `aria-multiselectable` | list.js: roving focus, Up/Down/Home/End, click/Enter/Space selects; `s4-select` on the item, `s4-change { value }` on the list | single |

**When to use what:** a list for scanning items of one kind on any screen size; a [table](#table) when people compare
several columns. Use **segmented** for settings-style groups on a plain surface; plain lists inside cards and panes.
Group by date or status with subheaders; put the group total in the subheader.

**Do**
- Keep the headline to one line; put detail in supporting text (sentence case).
- Right-align amounts in the trailing slot; they use tabular figures automatically.
- Use `aria-current="page"` for the current item in navigation lists, `aria-selected` only inside a listbox.

**Don't**
- Don't put two interactive controls in one interactive item (a link item with a switch in it).
- Don't mix one-, two- and three-line items in a list without reason; set `data-lines` on the list to even them out.
- Don't show status by color alone; use a [status](#status) pill with a label.

**Accessibility:** a `<ul>` of real links, buttons or labels needs no script. Interactive items have the shared state
layer and an inner focus ring (so it isn't clipped by a scrolling parent). A `label` item makes the whole row the
checkbox's or switch's label. Listboxes follow the WAI-ARIA listbox pattern. Forced-colors mode outlines the selected item
and segmented items.

**Tokens:** `--s4-size-list-item-one-line` / `-two-line` / `-three-line`, `--s4-shape-list-segment`,
`--s4-shape-list-group`, `--md-sys-color-secondary-container`, `--md-sys-color-on-secondary-container`,
`--md-sys-color-surface-container-low`, `--md-sys-color-primary-container`, `--md-sys-color-outline-variant`,
`--md-sys-typescale-body-large-*`, `-body-medium-*`, `-label-small-*`, `-title-small-*`, `-title-medium-*`,
`--md-sys-state-*`.

<a id="table"></a>

## Table

S4 addition (M3 has no current data table spec). Compares rows across columns: bills, payments, invoices. Sorting,
row selection, clickable rows, a sticky header, and a stacked layout on phones so nothing scrolls sideways. Tables are
solid content surfaces, never glass.

```html
<div class="s4-table-wrap" data-sticky>
  <table class="s4-table">
    <caption>October Bills</caption>
    <thead><tr>
      <th scope="col" data-check><label class="s4-checkbox"><input type="checkbox" aria-label="Select All Bills"><span class="s4-checkbox-box"></span></label></th>
      <th scope="col" data-primary aria-sort="none"><button type="button" class="s4-table-sort">Vendor<span class="s4-icon" data-icon="chevron-down"></span></button></th>
      <th scope="col">Status</th>
      <th scope="col" class="num" aria-sort="none"><button type="button" class="s4-table-sort">Amount<span class="s4-icon" data-icon="chevron-down"></span></button></th>
    </tr></thead>
    <tbody>
      <tr tabindex="0">
        <td data-check><label class="s4-checkbox"><input type="checkbox" aria-label="Select Iron Mountain INV-10482"><span class="s4-checkbox-box"></span></label></td>
        <td><a href="/bills/10482">Iron Mountain</a></td>
        <td><span class="s4-status" data-tone="tertiary">Due</span></td>
        <td class="num" data-value="1240">$1,240.00</td>
      </tr>
    </tbody>
    <tfoot><tr><th scope="row" colspan="3">Total</th><td class="num">$1,240.00</td></tr></tfoot>
  </table>
</div>
```

| Attribute / part | Values | Default |
|---|---|---|
| `.s4-table-wrap` | surface-container-low, large corners, scrolls sideways if it must; the container the compact layout measures | — |
| `data-sticky` (wrap or table) | header stays at the top while rows scroll inside the wrap; height from `--s4-table-max-height` | header + 8 rows |
| `th`, `td` | header 56 (title-small, on-surface-variant), rows 52 (body-medium), 16 side padding, tabular figures | — |
| `.num` on `th` / `td` | right-aligned (table.js copies it from the header to the column's cells) | start |
| `data-wrap` on `th` / `td` | let a long column wrap (min 192) | no wrap |
| `th[aria-sort]` + `button.s4-table-sort` | click cycles `ascending` → `descending` → `none` (original order); sorts each tbody by `data-value` or text; `s4-change { type: 'sort', column, label, direction }` | — |
| `data-value` on `td` | the sort key: a number for amounts, an ISO date for dates | the text |
| `th[data-check]`, `td[data-check]` | checkbox column; header box selects all (indeterminate for some); checked rows get secondary-container; `s4-change { type: 'select', rows }` | — |
| `tr[tabindex="0"]` | clickable row: state layer, click or Enter fires `s4-select { row }` and follows the row's first link | — |
| `th[data-primary]` | in the stacked layout, that column's cell is the block's headline | — |
| `data-label` on `td` | column name shown in the stacked layout; table.js copies it from the header; `data-label=""` hides it | header text |
| `tfoot` | totals, title-small | — |

**Compact (the wrap under 600):** each row becomes a block: the primary cell as a headline, then one line per cell with
its column name on the left and the value on the right. The header row becomes a toolbar with select-all and the sort
buttons; plain column names are hidden (each cell carries its own). A selectable row's checkbox sits at the block's top
start.

**When to use what:** a table when people compare values across columns or sort; a [list](#list) when each item is
read on its own. Keep tables to the columns that matter; put the rest on the detail page.

**Do**
- Right-align amounts and counts (`.num`), and give them `data-value` so they sort as numbers.
- Make one column `data-primary` (usually the name) so stacked rows read well on phones.
- Show status with a [status](#status) pill (a label and a tone).
- Label every row checkbox with what it selects ("Select Staples INV-10451").

**Don't**
- Don't make a row clickable and also fill it with buttons; one action per row, or a trailing icon button with
  `tabindex` off the row.
- Don't rely on sideways scrolling on phones; the stacked layout is there so you don't need it.
- Don't sort columns where order means nothing (descriptions).

**Accessibility:** a real `<table>` with `<caption>`, `scope`d headers and `aria-sort`, so screen readers announce the
column and sort order. Sorting is a native button in the header. Clickable rows are focusable with an inner focus ring and
open on Enter; the link inside stays the accessible way in. Forced-colors mode draws the wrap's border and outlines
checked rows.

**Tokens:** `--s4-size-table-header`, `--s4-size-table-row`, `--s4-size-touch-target`, `--md-sys-shape-corner-large`,
`--md-sys-color-surface-container-low`, `--md-sys-color-secondary-container`, `--md-sys-color-on-secondary-container`,
`--md-sys-color-outline-variant`, `--md-sys-typescale-title-small-*`, `-body-medium-*`, `-title-medium-*`,
`-label-large-*`, `--md-sys-state-*`, `--md-sys-motion-spring-spatial` (rows slide into their sorted place),
`--md-sys-motion-spring-fast-spatial` (sort arrow).

## Divider

A thin line that groups content (M3). 1px outline-variant.

```html
<hr class="s4-divider">
<hr class="s4-divider" data-inset="start">
<hr class="s4-divider" data-inset="middle">
<hr class="s4-divider" data-orientation="vertical">
```

| Attribute | Values | Default |
|---|---|---|
| `data-inset` | `start` (16 at the start), `middle` (16 at both ends); on a vertical divider, 8 at the top (and bottom) | full width |
| `data-orientation` | `vertical`: a line between items in a flex or grid row; stretches to the row's height (24 minimum) | horizontal |
| `--s4-divider-inset` | the inset length, e.g. `calc(var(--s4-space-4) * 2 + var(--s4-space-10))` (72) to line up with list text after an avatar | 16 |

**When to use what:** prefer space and surface color to separate things. Use a full-width divider between groups, an
inset divider between items of a list, and a vertical one between figures in a row. For lines between every list item,
use the list's `data-dividers` instead.

**Do**
- Use a real `<hr>` when it separates sections of content; it's announced as a separator.

**Don't**
- Don't stack a divider against a surface edge or another divider.
- Don't color dividers; they are always outline-variant.

**Accessibility:** `<hr>` has the `separator` role. A purely decorative vertical divider in a toolbar can take
`aria-hidden="true"`. The line is a real border, so it survives forced-colors mode.

**Tokens:** `--s4-size-divider`, `--md-sys-color-outline-variant`, `--s4-space-2`, `--s4-space-4`, `--s4-space-6`.

```html
<div class="s4-text-field" data-error="Enter an amount above $0.00."> … </div>
<div class="s4-text-field"><select id="cat"><option value=""></option><option>Utilities</option></select><label for="cat">Category</label></div>
<div class="s4-text-field" data-counter><textarea id="notes" rows="1" maxlength="120"></textarea><label for="notes">Notes</label></div>
```

| Part / attribute | Meaning |
|---|---|
| `<input id>` / `<select>` / `<textarea>` + `<label for>` | the control and its floating label (body large → body small) |
| `data-variant="outlined"` | outlined; default is filled (surface-container-highest, top corners `--s4-shape-text-field`, 1dp indicator → 2dp primary on focus) |
| `.s4-icon` / `.s4-icon-button` before the control | leading icon (12dp from the edge, 16dp to the text) |
| `.s4-icon` / `.s4-icon-button` after the control | trailing icon or action |
| `.s4-text-field-affix[data-prefix]` / `[data-suffix]` | "$", "kg": shown once the label floats |
| `.s4-text-field-supporting` | helper text, sentence case |
| `data-counter` | "length / maxlength" at the end of the supporting line |
| `data-error="Message"` (or `aria-invalid="true"` on the control) | error color; the message replaces the helper text |
| `disabled` on the control | M3 disabled: 4% container, 38% content |

**Behaviour** (`text-field.js`): adds `placeholder=" "` so the label can float with `:placeholder-shown` (a real
placeholder is shown only while focused); injects the outlined notch; adds a chevron to selects and opens the picker
when the field is clicked; grows textareas; links supporting text with `aria-describedby`; keeps `aria-invalid` and the
error message in sync with `data-error`. Selects float their label when a non-empty option is chosen (`value=""` keeps
it resting); date/time inputs always float.

**The outlined notch** is a real `<fieldset><legend>` drawn behind the control (`.s4-text-field-outline`, `aria-hidden`).
The browser cuts the border around the legend, which holds an invisible copy of the label at body-small, so the gap is
exactly the label's width on any background — glass, images, gradients — with no background patch to match. The legend
width animates open on the same calm spring as the label.

**Do**
- Title Case labels ("Due Date"), sentence-case helper and error text that says how to fix it.
- Use `inputmode="decimal"` and a `$` prefix for amounts; the field already uses tabular figures.

**Don't**
- Don't use the placeholder as the label.
- Don't put helper text and an error in two places; `data-error` replaces the helper text.

**Accessibility:** native controls with real `<label for>`; supporting text is `aria-describedby`; errors set
`aria-invalid`; the active indicator / outline is the focus indication (M3); the whole container is a click target;
forced-colors mode draws real borders.

**Tokens:** `--s4-size-text-field`, `--s4-shape-text-field`, `--md-sys-color-surface-container-highest`,
`--md-sys-typescale-body-large/body-small-*`, `--s4-motion-spring-fast-spatial-calm` (label), `--md-sys-state-*`.

```html
  <button class="s4-chip" data-type="filter" type="button">Office</button>
</div>
<div class="s4-chip-set" data-select="single" data-scroll aria-label="Status"> … filter chips … </div>
<div class="s4-chip-set" aria-label="Tags">
  <span class="s4-chip" data-type="input">Travel<button class="s4-chip-remove" type="button" aria-label="Remove Travel"></button></span>

<button class="s4-chip" data-type="suggestion" type="button">Pay in Full</button>
```

| Attribute | Values | Default |
|---|---|---|
| `data-type` | `assist`, `filter`, `input`, `suggestion` | `assist` |
| `aria-pressed` | filter chip state | `false` |
| `data-elevated` | surface-container-low + level 1 shadow instead of the outline | — |
| `disabled` / `aria-disabled="true"` | disabled | — |
| `.s4-chip-set[data-select="single"]` | exactly one filter chip pressed | multi |
| `.s4-chip-set[data-scroll]` | one horizontally scrolling row | wraps |

secondary-container / on-secondary-container with no outline, and a check slides in (fast-spatial width animation),

**Behaviour** (`chip.js`): filter chips toggle `aria-pressed` and fire `s4-change { pressed }` on the chip. Input chips:
`.s4-chip-remove` gets a close icon; a click (or Delete / Backspace on it) fires a cancelable `s4-remove { chip }`
(call `preventDefault()` to keep the chip), then the chip collapses and is removed and focus moves to its neighbour.

**When to use what:** filter chips to narrow a list; input chips for values someone entered (tags, people);
assist chips for a related action ("Add to Calendar"); suggestion chips for likely values or replies.

**Do:** Title Case labels, 1–3 words; give each remove button an `aria-label` naming the chip.
**Don't:** use chips as primary actions (use buttons) or for navigation (use tabs).

**Accessibility:** filter, assist and suggestion chips are `<button>`s (`aria-pressed` for filters); the remove control is
its own button; 48dp touch targets; forced-colors mode draws borders.

**Tokens:** `--s4-size-chip`, `--s4-shape-chip`, `--md-sys-color-secondary-container`, `outline-variant`,
`surface-container-low`, `--md-sys-elevation-level1/2`, `--md-sys-typescale-label-large-*`,

## Slider

Picks a value from a range. M3 Expressive slider on a native `<input type="range">`.

```html
<label for="budget">Monthly Budget</label>

  <input type="range" id="budget" min="0" max="2000" step="10" value="1240">
```

| Attribute (on `.s4-slider`) | Meaning |
|---|---|

## Swatches

S4's seed-color picker, like Android's Wallpaper & style: each swatch previews the palette a seed makes, and picking one
themes the app.

```html
<div class="s4-swatches" data-theme-seed aria-label="Theme Color">
  <button class="s4-swatch" type="button" data-seed="#000000" aria-label="Mono"></button>
```

| Attribute | Meaning |
|---|---|

## Badge

Shows that something is new, or how many items need attention (M3). Error and on-error.

```html
<span class="s4-badge"></span>          <!-- small: 6dp dot -->
<span class="s4-badge">3</span>         <!-- large: 16dp, label-small -->
<span class="s4-badge">999+</span>
```

| Part | Values | Default |
|---|---|---|

| `.s4-badge` with text | large: 16 high, at least 16 wide, 4 side padding, label-small, tabular figures | — |
| `.s4-badge-host` | wraps an icon; the small dot sits in the icon's top-end corner, a large badge starts 12dp in from the icon's end with its bottom 14dp below the icon's top (M3 / Compose `BadgedBox` offsets) | — |

**When to use what:** the **small** dot when the count doesn't matter ("something new"); the **large** badge for a count.

## Status

S4 addition. A small pill that names the state of a thing: a bill, a payment, a sync. The label always says the status
in words; the tone and the optional dot only reinforce it, so status never relies on color alone.

```html
<span class="s4-status">Paid</span>
<span class="s4-status" data-tone="tertiary">Due</span>
<span class="s4-status" data-tone="error" data-dot>Overdue</span>
<span class="s4-status"><span class="s4-icon" data-icon="check"></span>Paid</span>
```

| Attribute | Values | Default |
|---|---|---|
| `data-tone` | `primary`, `secondary`, `tertiary`, `error`: the matching container / on-container roles | neutral: surface-container-high / on-surface-variant |
| `data-dot` | a 6dp leading dot in the text color | — |
| leading `.s4-icon` | a 16dp icon instead of the dot | — |

24 high, 8 side padding, small corners (8), label-medium, tabular figures, no wrapping.

**When to use what:** pick tones by meaning and keep them consistent across an app. For bills: Paid is neutral,
Scheduled is primary, In Review is secondary, Due is tertiary, Overdue and Failed are error. Use one error tone per
meaning; don't escalate with more colors.

**Do**
- Use one or two words in Title Case ("Due", "Payment Failed"); add a date when it helps ("Due Nov 2").
- Put the pill next to the thing it describes (in the row, after the amount).

**Don't**
- Don't make a status clickable; to filter by status, use a filter chip.
- Don't use the error tone for anything that isn't a problem.
- Don't use a badge for status; badges count things.

**Accessibility:** the text is the status, so screen readers read it as is, and it works in grayscale and forced colors
(which draws a border). Container / on-container pairs pass AA in every scheme.

**Tokens:** `--md-sys-color-surface-container-high`, `--md-sys-color-on-surface-variant`,
`--md-sys-color-{primary,secondary,tertiary,error}-container`, `--md-sys-color-on-{primary,secondary,tertiary,error}-container`,

<a id="progress"></a>

## Progress

Shows that something is happening (M3 Expressive): linear or circular, determinate or indeterminate. M3E details: a 4dp
gap between the indicator and the track, rounded ends, and a stop dot at the end of a linear track.

```html
<div class="s4-progress" data-value="0.62" aria-label="Q4 Budget Used"></div>              <!-- linear, determinate -->
<div class="s4-progress" aria-label="Syncing With Your Bank"></div>                       <!-- linear, indeterminate -->
<div class="s4-progress" data-type="circular" data-value="0.4" aria-label="Scanning"></div>
<div class="s4-progress" data-type="circular" aria-label="Loading Bills"></div>
```

| Attribute | Values | Default |
|---|---|---|
| `data-type` | `linear`, `circular` | `linear` |
| `data-value` | 0 to 1 (clamped); leave out for indeterminate. Change it at any time; the indicator moves with a spring | indeterminate |
| `aria-label` | what is in progress (required) | — |

progress.js sets `role="progressbar"`, `aria-valuemin="0"`, `aria-valuemax="100"`, `aria-valuenow` (removed when
indeterminate) and the internal `--_value`, and draws the circular indicator's SVG.

**Linear:** full width, 4dp high; primary indicator, secondary-container track, 4dp stop dot in primary at the track's end
(it disappears at 100%). **Circular:** 40dp, 4dp stroke with round caps; the track shows only while determinate.

**Public knobs.** The indeterminate loops are long, linear cycles that no spring token describes, so they are
component-level custom properties:

| Property | What | Default |
|---|---|---|
| `--s4-progress-cycle` | linear indeterminate cycle (M3: two lines, 1800ms) | `1800ms` |
| `--s4-progress-circular-cycle` | circular arc grow-and-catch-up cycle | `1333ms` |
| `--s4-progress-circular-spin` | circular rotation | `2000ms` |

**Reduced motion.** This component carries the one allowed `@media (prefers-reduced-motion: reduce)` query: tokens can't
stop an infinite loop, so the indeterminate animations stop and show a still, partial indicator (40% of the linear bar,
a quarter arc). `:root[data-motion="reduced"]` (S4.motion's app switch) does the same. Determinate changes use the
calm spatial spring, which the tokens already zero under reduced motion.

**When to use what:** **linear** at the top of a surface or under the thing it describes (an upload, a budget); **circular**
in a small space (a button, a card corner, a full-screen load). Use **determinate** whenever you know the fraction.

**Do**
- Label it with what is happening ("Uploading Receipts"), and show the figure next to it when it means something
  ("$6,820.00 of $11,000.00").
- Remove the indicator when the work is done; don't leave a full bar on screen.

**Don't**
- Don't show a progress indicator for actions under about a second.
- Don't stack several indeterminate indicators on one screen.

**Accessibility:** a real `progressbar` with a name and value. Forced-colors mode draws the linear track with a border and
the indicator in CanvasText.

**Tokens:** `--md-sys-color-primary`, `--md-sys-color-secondary-container`, `--s4-space-1` (thickness and gap),
`--s4-space-10` (circular size), `--md-sys-shape-corner-full`, `--s4-motion-spring-spatial-calm` (value changes),
`--md-sys-motion-spring-slow-effects` (indeterminate easing per segment).

<a id="snackbar"></a>

## Snackbar

A short message after an action, often with Undo. **Slides up from the bottom edge**, above a nav bar, docked toolbar or FAB.
A solid inverse surface (not glass), so its `inverse-primary` action keeps 4.5:1.

```js
S4.snackbar({ text: 'Bill archived', action: 'Undo', onAction: restore });
S4.snackbar('Staples marked as paid');
S4.snackbar({ text: 'Couldn’t sync 3 bills. Check your connection.', action: 'Retry', multiline: true, closable: true });
```

| Option | Default |
|---|---|
| `text` | required; sentence case, past tense for confirmations ("Bill archived") |
| `action`, `onAction` | one short action, usually Undo or Retry |
| `closable` | adds a close icon button |
| `multiline` | text on its own line, action below |
| `duration` | 4000ms, or 6000ms with an action; `0` keeps it until dismissed |

Returns `{ element, dismiss() }`. One at a time: a new snackbar replaces the current one. It pauses while hovered or focused,
and is announced politely to screen readers.

**Do:** confirm actions that already happened, offer Undo instead of a confirm dialog. **Don't:** use it for errors that need
a decision (use a dialog) or for messages that must stay (use a banner or inline text).

<a id="tooltip"></a>

## Tooltips

**Plain** tooltips name an icon-only control: `data-tooltip="Copy invoice number"`. They appear after a 500ms hover, on
keyboard focus, or on a long press; Escape hides them; they can be hovered (WCAG 1.4.13). Solid inverse surface.

**Rich** tooltips explain something in a few lines and may hold an action; they sit on glass:

```html
<button class="s4-button" data-variant="text" data-rich-tooltip="autopay-tip">What Is Autopay?</button>
<div class="s4-rich-tooltip" id="autopay-tip" role="dialog" aria-label="About Autopay">
  <span class="s4-rich-tooltip-subhead">Autopay</span>
  <span>Pays the bill from your default card on its due date.</span>
  <div class="s4-rich-tooltip-actions"><button class="s4-button" data-variant="text">Learn More</button></div>
</div>
```

Hover or focus shows a rich tooltip; a click pins it until you click elsewhere.

**Do:** keep plain tooltips to a few words that name the action. The control still needs its own `aria-label`; the tooltip
is linked with `aria-describedby` (added to any existing ids, never replacing them). **Don't:** put essential information
only in a tooltip, or put interactive content in a plain one.

## Menu

A short list of choices opened from a button. **Unfolds** from the edge next to its button (the menu's shape opens; items

```html
<button class="s4-button" data-variant="tonal" data-menu="sort-menu">Sort By</button>
<div class="s4-menu" id="sort-menu" aria-label="Sort by">
  <div class="s4-menu-label">Sort By</div>
  <button class="s4-menu-item" role="menuitemradio" aria-checked="true"><span class="s4-icon" data-icon="calendar"></span>Due Date</button>
  <button class="s4-menu-item" role="menuitemradio" aria-checked="false"><span class="s4-icon" data-icon="wallet"></span>Amount</button>
  <hr class="s4-menu-divider">
  <button class="s4-menu-item" data-color="error"><span class="s4-icon" data-icon="delete"></span>Delete</button>
</div>
```

| Part / attribute | Use |
|---|---|
| `[data-menu="id"]` on the opener | Opens the menu; gets `aria-haspopup`, `aria-expanded`, `aria-controls` |
| `.s4-menu[data-align="end"]` | Align the menu's end edge with the opener (for overflow menus at the right) |
| `.s4-menu[data-color="vibrant"]` | Tertiary-container menu |
| `.s4-menu-item` + `.s4-menu-item-text`, `.s4-menu-item-supporting`, `.s4-menu-item-trailing` | Item, with optional second line and a shortcut or value at the end |
| `role="menuitemradio|menuitemcheckbox"` + `aria-checked` | Choice items; checked items use secondary-container |
| `.s4-menu-label`, `.s4-menu-divider` | Group label, separator |
| Events | `s4-select { value, item }` on the menu when an item is chosen; `s4-open`, `s4-close` |
| JS | `S4.menu.open(menu, anchor)`, `S4.menu.close(menu)`, `S4.position(popup, anchor, { align, gap })` |

**Do:** keep menus short (2–7 items), Title Case items, icons for every item or none. **Don't:** put forms or long text in a
menu (use a dialog or sheet); don't color items except a destructive one.

**Accessibility:** native popover (top layer, light dismiss); arrows, Home/End, type-to-jump, Escape returns focus to the
opener; Tab closes. 48dp item targets.

<a id="dialog"></a>

## Dialog

Asks for a decision or a short input. The button you press **becomes** the dialog (container transform): its shape and
color grow into the dialog at real size while the label fades out and the content fades in; closing runs it back into
the button. On glass, over a 32% scrim.

```html
<button class="s4-button" data-color="error" data-dialog="confirm-delete">Delete Bill</button>
<dialog class="s4-dialog" id="confirm-delete" aria-labelledby="cd-h">
  <span class="s4-icon s4-dialog-icon" data-icon="delete"></span>
  <h2 class="s4-dialog-headline" id="cd-h">Delete this bill?</h2>
  <div class="s4-dialog-content">Staples, $72.40. This can’t be undone.</div>
  <div class="s4-dialog-actions">
    <button class="s4-button" data-variant="text" data-close="cancel">Cancel</button>
    <button class="s4-button" data-variant="text" data-color="error" data-close="delete">Delete</button>
  </div>
</dialog>
```

| Attribute / API | Use |
|---|---|
| `[data-dialog="id"]` | Opens the dialog from this element (container transform) |
| `[data-close="value"]` | Closes it; the value comes back in `s4-close { value }` |
| `data-fullscreen="compact"` | Full screen on phones. Needs **both** markups: the normal headline + actions (wide screens) and a `.s4-dialog-bar` (phones) holding a close icon button (`data-close="cancel"`), a `.s4-dialog-headline` and a confirm text button; the other set is hidden at each size |
| `data-persistent` | A click on the scrim doesn't close it (Escape still does) |
| `data-origin="none"` | Fade in place instead of growing from the opener |
| JS | `S4.dialog.open(id, { from })`, `S4.dialog.close(id, value)`; events `s4-open`, `s4-close` |

**Focus:** `[autofocus]` wins; otherwise the first focusable element that isn't destructive, so Enter never confirms a delete
by accident. Focus returns to the opener.

**Do:** questions as headlines in sentence case ("Delete this bill?"); actions say what they do ("Delete", not "OK"); confirm
only what can't be undone (use Undo in a snackbar otherwise). **Don't:** stack dialogs; put a dialog on a sheet.

<a id="sheet"></a>

## Sheets

A short task without leaving the screen. **Bottom sheets** grow out of a FAB (container transform) or, opened from anything
else, **slide from the bottom edge**; drag the handle down to dismiss. **Side sheets** slide from the end edge. Both on glass.

```html
<button class="s4-fab" data-sheet="add-expense" aria-label="Add expense"><span class="s4-icon" data-icon="add"></span></button>
<dialog class="s4-bottom-sheet" id="add-expense" aria-labelledby="ae-h">
  <span class="s4-sheet-handle" aria-hidden="true"></span>
  <h2 class="s4-sheet-title" id="ae-h">Add Expense</h2>
  <div class="s4-sheet-content">…fields…</div>
  <div class="s4-sheet-actions"><button class="s4-button" data-variant="text" data-close="cancel">Cancel</button><button class="s4-button" data-close="save">Save</button></div>
</dialog>
<dialog class="s4-side-sheet" id="filters">
  <div class="s4-sheet-header"><h2 class="s4-sheet-title">Filters</h2><button class="s4-icon-button" data-close aria-label="Close"><span class="s4-icon" data-icon="close"></span></button></div>
  …
</dialog>
```

Opening, closing, `[data-close]`, `data-persistent`, focus and events work exactly like the [dialog](#dialog)
(`S4.sheet.open/close` are the same functions). Drag-dismiss fires `s4-close { value: "drag" }`.

**Do:** use a bottom sheet for a quick add or a set of choices on phones; a side sheet for filters or details beside content on
wide screens. **Don't:** put a sheet on a dialog, or a second sheet on a sheet.
